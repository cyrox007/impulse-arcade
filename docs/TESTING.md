# Проверки «Импульса» 1.0 RC

## Быстрый прогон

```bash
npm run check
```

Команда проверяет синтаксис всех девяти игровых JS-файлов (`game-storage`, `game-ui`, `game-physics`, `game-bricks`, `game-bosses`, `game-effects`, `game-render`, `game`, `game-input`) и запускает Node.js `node:test`. Минимум Node.js 20, сторонних npm-зависимостей для самой игры нет.

Наборы тестов разделены по ответственности:

| Набор | Назначение |
| --- | --- |
| `tests/foundation.test.cjs` | Запуск, состояния, управление, базовые столкновения, производительность спрайтов |
| `tests/brick-effects.test.cjs` | Комбо, бонусы, кирпичи, эффекты, подвижные объекты, Страж |
| `tests/bosses.test.cjs` | Мультишар, боссы, импульсы, направленные кирпичи, снаряды |
| `tests/persistence.test.cjs` | Контрольная точка, настройки, восстановление, стресс-сценарии |

Тесты используют единый `tests/support/game-harness.cjs`. Он поднимает Canvas- и DOM-заглушки, часы `requestAnimationFrame`, `localStorage` и загружает все девять игровых скриптов в том же порядке, что и сайт. **Не копировать** этот стенд в каждый файл тестов: исправления окружения должны быть общими.

Отдельный набор можно запустить командой:

```bash
node --test tests/bosses.test.cjs
```

## Браузерные проверки

```bash
python -m pip install playwright
python -m playwright install chromium
python tests/browser_smoke.py
```

Проверяются desktop и четыре мобильных viewport, взаимодействие, пауза, настройки, рендер и восстановление контрольной точки после перезагрузки. Дополнительно открывается настоящий локальный `index.html` через `file://` для проверки порядка и доступности статических скриптов.

Браузерные тесты не измеряют реальные 60 FPS на конкретном физическом смартфоне и не заменяют ручное прохождение пяти секторов с двумя боссами.

## Правила изменений

1. Для ошибок физики сначала записать воспроизводимый тест с состоянием мяча, координатами, скоростью и типом столкновения.
2. Для ошибок ввода использовать события браузера и отдельно проверять настройки, фокус и одновременные касания.
3. Для сохранений проверять новую сессию, некорректные данные и отказ `localStorage`.
4. Изменение размеров Canvas/CSS/порядка подключения скриптов требует полного Chromium smoke.
5. Не повышать статус релиза до stable только по факту успешного CI; контрольный список ручной приёмки — `docs/RELEASE-1.0-QA.md`.

## Ветки

`develop` — текущая интеграционная линия RC1. `main` — старая опубликованная основа до ручной приёмки. Старые feature-ветки не удалять автоматически: сначала проверить уникальные коммиты и историю PR.
