# ИМПУЛЬС — браузерный арканоид

**Актуальная разработка:** `1.0.0-rc.1` в ветке [`develop`](https://github.com/cyrox007/impulse-arcade/tree/develop). Это **релиз-кандидат**, не стабильная версия 1.0. Ветка `main` остаётся прежней опубликованной основой до итоговой приёмки.

Оригинальная аркада на JavaScript и Canvas 2D: пять секторов, разные виды кирпичей, Страж ядра в третьем секторе и финальный Реактор в пятом. Поддерживаются мультишар (до трёх), магнитная платформа, барьер, бонусы, пробивной импульс, комбо и локальные контрольные точки.

## Запуск

Никакого сборщика и внешних JS-библиотек не требуется: откройте `index.html` напрямую или разместите репозиторий на статическом сервере. Если нужна именно версия RC, переключитесь на `develop` — опубликованная страница из `main` может отставать.

- **ПК:** мышь или стрелки / A, D; пробел — запуск, F — импульс, P или Esc — пауза.
- **Телефон:** перемещайте платформу пальцем по игровому полю, используйте кнопки снизу.
- **Настройки:** ⚙ — громкость, чувствительность и эффекты. При настройке активная игра ставится на паузу; закрытие панели не запускает игру само.
- **Сохранения:** рекорд, настройки и контрольные точки хранятся в `localStorage` конкретного браузера. Точка создаётся после завершения сектора, но не посреди боя. Очистка данных браузера уничтожает локальный прогресс.
- **Диагностика:** `?fps=1` включает измерение кадров на самом устройстве.

## Устройство проекта

| Файл | Назначение |
| --- | --- |
| `game.js` | Центральное состояние и жизненный цикл кампании |
| `game-physics.js` | Шары, отражения, подвижные препятствия, геометрия попаданий |
| `game-bricks.js` | Сектора, кирпичи, комбо, очки и взрывной урон |
| `game-bosses.js` | Страж, Реактор и их атаки |
| `game-effects.js` | Бонусы, таймеры, частицы и волны |
| `game-storage.js` | Рекорд, настройки и контрольные точки |
| `game-ui.js` | DOM, панель настроек, экраны и статистика |
| `game-render.js` | Canvas, спрайты и кэш графики |
| `game-input.js` | Клавиатура, сенсор, кадровый цикл и диагностика |

Файлы загружаются обычными `<script defer>` в определённом порядке; они разделяют **один экземпляр `Game`**, а не создают дублирующие состояния. Подробности и ограничения: [архитектура](docs/ARCHITECTURE.md).

## Проверка изменений

Нужен Node.js 20 или новее. Перед проверкой установите инструменты разработки:

```bash
npm ci
npm run format:check
npm run check
```

Для автоматического оформления изменённых игровых файлов и тестов:

```bash
npm run format
```

Prettier используется только при разработке: игра по-прежнему запускается без сборщика и npm-зависимостей.

Проверки в реальном Chromium (Playwright устанавливается отдельно):

```bash
python -m pip install playwright
python -m playwright install chromium
python tests/browser_smoke.py
```

В CI проверяются синтаксис, игровые регрессии, desktop и четыре мобильных размера, восстановление сохранения после перезагрузки и локальный запуск `file://`. Полные инструкции: [тестирование](docs/TESTING.md).

**Важно:** успешный CI не подтверждает плавность FPS и прохождение игры на физическом Android. До стабильной 1.0 необходимо пройти [контрольный список ручной приёмки](docs/RELEASE-1.0-QA.md).
