# Правила разработки «Импульса»

## Цель

Поддерживаем понятную автономную игру на Canvas 2D, а не универсальный игровой движок. Внешние библиотеки, сборщик, фреймворк и новая абстракция добавляются только если они решают воспроизводимую задачу. Убедительная простота важнее количества классов.

## Где изменять код

Физика — `game-physics.js`, кирпичи — `game-bricks.js`, боссы — `game-bosses.js`, бонусы и эффекты — `game-effects.js`, DOM — `game-ui.js`, сохранения — `game-storage.js`, Canvas — `game-render.js`, управление — `game-input.js`. `game.js` отвечает за общий жизненный цикл игры.

Методы подсистем подключены к прототипу `Game` **до** создания экземпляра. Нельзя создавать отдельный объект-источник статистики, списка шаров, состояния босса или контрольной точки: все модули работают с тем же `this`.

Порядок скриптов `index.html`, `tests/support/game-harness.cjs` и `tests/browser_smoke.py` синхронизирован. Добавление нового скрипта требует изменения всех трёх мест и `npm run check`.

## Читаемость

- Имена методов описывают действие, а имена состояний соответствуют текущей модели.
- Новые методы должны быть короткими и решать одну задачу. Не объединять десятки присваиваний в одну строку.
- Комментарии — на русском; объясняют **почему** применяются подшаги физики, ограничения чисел, порядок удаления объектов или обработка недоступного хранилища.
- Не дублировать очевидные строки комментариями и не создавать классы без самостоятельной ответственности.
- Диагностика и пользовательские сообщения, которые контролирует сам проект, — на русском.
- Отступы и кодировка определены `.editorconfig`. Форматирование управляется `.prettierrc.json` (Prettier 3.6.2), а не личными настройками редактора.
- Перед PR выполните `npm ci`, `npm run format` и `npm run format:check`. Не создавайте вручную минифицированные или склеенные однострочные методы.

## Проверка до PR

1. Изменение физики или правил игры начинается с воспроизводимой Node-регрессии.
2. Изменение UI/CSS/Canvas или порядка загрузки требует Chromium smoke на всех размерах.
3. Изменение хранения проверяется для пустых, повреждённых и запрещённых `localStorage`.
4. Выполнить `npm run format:check`, `npm run check` и `python tests/browser_smoke.py`.
5. В PR указать, какие игровые параметры изменились. Если это чистый рефакторинг — отметить, что баланс и формат сохранений не менялись.

Только после реального тестирования на Android и выполнения [контрольного списка релиза](docs/RELEASE-1.0-QA.md) возможен перенос версии в `main`.
